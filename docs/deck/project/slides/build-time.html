1 - Modules

Build time — the bundler resolves it

you wrote

'@angular/core'

it shipped

_angular_core.AnS7MGp98i.js

The bundler had node_modules on a disk. The browser never will.

Three moments, one at a time. This is the first, and it is the one almost everybody is already using without thinking about it. At build time, the bundler does the resolving. It reads a specifier, goes looking on the file system, finds the package inside node_modules, and writes the answer into the output. Here is what that looks like. On the top line, what was written in the source: at-angular-slash-core. On the bottom, the file that came out of the build. The bundler has taken the package, bundled it into a chunk, given it a name of its own and a content hash so it can be cached forever. And notice what is no longer there. The name is gone. Nothing in that output needs looking up any more, because the lookup already happened — on a machine, months or minutes ago, with a disk full of packages on it. Which is the thing to hold on to, and the reason the other two moments exist at all. The bundler could do this because node_modules was sitting right there. A browser has no node_modules. It has never had one, and it never will. So the moment you want a name resolved anywhere other than at build time, somebody has to answer the question a different way. [Two lines. Point at the top one, then the bottom one. The last sentence is the one that matters.]
