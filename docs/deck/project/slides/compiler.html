Prototype. In angular/main since 8 October 2026 — not released as of 24 October 2026.

So if the way in is closed, you stop going in. You build your own compiler. That is what this is. It is called ngp, it has been in Angular's main branch since the eighth of October, and their own README opens with the word Caution: early-stage prototype, not accepting outside contributions. So nothing here is a promise. Two things changed. One is interesting. The other is the one that matters. The interesting one is the frontend. The orange half — the global, slow half — has been rewritten in Rust, on oxc — the same toolchain underneath Vite. It is multithreaded, which is why it will be fast. The blue half did not move: the backend is still TypeScript, still the same template compiler Angular has always had. What changed in it is only the last step. The old backend handed its result to TypeScript, through ts.Transformer, which is why it had to run inside TypeScript. The new one prints the characters into a file. That is the whole reason it can stand on its own. The one that matters is in the shape of the picture, not in either box. Look at the top row. The compiler is inside the bundler. That was not a design choice anybody made for fun — it was forced. Angular's output never existed anywhere you could pick it up. It was a syntax tree, inside a running TypeScript process, for a few milliseconds. The only way to receive it was to be in that process, as a plugin. So the bundler had to host Angular's compiler inside itself. Which is why every bundler that builds Angular needs an adapter written specially for it. Somebody has to write the plugin that drives the compiler and hands the results around. That is what @nx/angular-rspack is. That is what the Analog plugin is for Vite. Somebody maintains each one. Now look at the bottom row. The compiler runs first, on its own, and leaves two files behind — one per job. The ng dot ts file is your code with the decorator already replaced; that is what the bundler takes. The ngtypecheck file is the templates rewritten as TypeScript; that is what tsc takes, to give you template errors. Same two jobs as before, but now each one ends in a file instead of inside somebody's process. And that is not a plan — it is already there. There is a command in the branch today: you point ngp at a tsconfig, give it an output directory, and it writes you a folder of TypeScript. No bundler involved, nothing hosting anything. Ordinary TypeScript, with the decorator already replaced by the definition. The bundler is no longer hosting anything. It is just reading TypeScript — which every bundler on earth already does. esbuild reads it. Rspack reads it. Vite reads it. Something you write this afternoon reads it. The adapter has nothing left to adapt. [Point at the nesting in the top row, then at the gap in the bottom row. That gap is the whole slide.]
