3 - Bundlers

Vite pipeline

Why it is probably not an option

There is no federation reason to use Vite, unless you are very interested in its ecosystem.

Chunk URL rewriting is not possible.

Unused shared modules are not automatically pruned.

There is no real advantage over the Angular CLI capabilities.

So: the two custom pipelines, one at a time, each against the thing you already have. The weaker case first. The first line is the honest headline. There is no federation reason to reach for Vite. What you would gain on the federation side does not come from Vite, it comes from Module Federation — and it is the same whichever bundler you run it on. What Vite does give you is its own ecosystem: Vitest for testing, Storybook for components in isolation, Astro if you are putting Angular into a documentation site. If you want that, want it for itself. Chunk URL rewriting is not possible, and the reason is Rolldown. It writes real import statements into the output with the paths inside them. The address of a chunk is in the statement, so there is no variable anywhere to reassign while the application is running. Shared modules are not pruned for you, and this one costs real bytes on the day. The federation plugin emits a chunk for every package you declare as shared, not for every one you actually use. Declare all your dependencies and the Angular compiler — six hundred kilobytes of it — ships into every application, for nothing. The Angular CLI prunes that automatically. Here you keep the list by hand. And the last line is the summary of the other three. Against the capabilities the CLI already gives you, there is nothing here you are gaining. [Four lines, read them plainly. The first is the one that does the work.]
