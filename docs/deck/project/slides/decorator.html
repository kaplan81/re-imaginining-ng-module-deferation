This is not a TypeScript decorator

@Component({

  selector: 'cat-bean-grid',

  imports: [CurrencyPipe, DecimalPipe],

  templateUrl: './bean-grid.component.html',

  styleUrl: './bean-grid.component.scss',

})

export class BeanGridComponent { … }

A component decorator. A selector, two pipes it imports, a template file, a stylesheet, and a class underneath. TypeScript does have decorators. Microsoft added them to the language years ago, and Alex Rickabaugh from the Angular team will tell you they were added largely because Angular needed them. So it would be reasonable to assume this is one of those. It is not. This is Angular's own decorator, and it behaves nothing like TypeScript's. A TypeScript decorator is a function. It runs. At runtime, when the class is defined, the function is called and it can do something to the class. This one never runs. In the build that reaches your users it is not there at all — open the bundle and search for the word Component and you will not find it. It was read at compile time, by a compiler, and then deleted. Everything inside those braces is metadata. A description. The selector is a description of how to find this component in HTML. The imports are a description of what the template is allowed to use. The HTML is metadata. The SCSS is metadata. None of it is code that runs. So if it is a description rather than instructions, something has to read it and turn it into something that does run. That something is what the next few minutes are about. [Five lines on screen, so do not read them out. Point at styleUrl and templateUrl when you reach "the HTML is metadata, the SCSS is metadata".]
