A build tool is not a bundler

Build tool

Contains a bundler, plus a dev server, TypeScript, stylesheets, assets.

Bundler

Walks the module graph and splits it into chunk files.

A build tool has defaults. For example Rsbuild compiles .ts with no configuration whereas Rspack needs a rule pointing at a loader.

Last section, and it is about the thing that actually assembles your application. It starts with a distinction that gets skipped almost everywhere, including in the earlier version of this talk. And there is a one-sentence version of it worth borrowing: build tools have defaults, and bundlers do not. Start at the top, and the important word is contains. A build tool holds a bundler inside it, and then a great deal more around it. Take Rsbuild, since it is on the table. Rspack is in there, doing the bundling. But so is a dev server, so is the thing that compiles your TypeScript, so is the stylesheet pipeline, so is the handling of images and fonts. You install one package and all of it arrives together. So a build tool is mostly not bundling. It is everything around the bundling — which is why one command gives you a working application instead of a configuration file. Vite is a build tool. Rsbuild is a build tool. Underneath it, a bundler has a much narrower job. It takes your module graph — every file and every import — and splits it into chunk files. Deciding how many there are and which modules go in each one is the whole of code splitting. That is what a bundler does, and it will not guess at anything you have not told it. The line underneath is the clearest example of the difference, and the two names in it sit on the same row of the table. Rsbuild and Rspack come from the same team, and Rsbuild is built on Rspack. Hand Rsbuild a TypeScript file and it compiles it — nothing to configure, it already knows. Hand the same file to Rspack and nothing happens, because Rspack has no opinion about what a dot-ts file is. You write a rule that says: for files matching this pattern, use this loader. Same compiler underneath, in both cases. One of them decided for you. That is the whole distinction. Which is also why the name people say out loud is almost always the one on the left of this table. You say you are using Vite. The thing doing the bundling is Rolldown. You say ng build. The thing doing the bundling is esbuild. Most people have never needed to know the second column exists. And the two layers move independently. Vite used to bundle with Rollup, and used esbuild for part of its work. As of Vite eight, esbuild is not a dependency at all any more and Rolldown is underneath. The build tool kept its name. The bundler changed. So when the next slide says three pipelines, it means three combinations of these two layers — and that is before federation enters the picture at all. [Two rows, the table, then the example. Defaults is the word that makes it stick.]
