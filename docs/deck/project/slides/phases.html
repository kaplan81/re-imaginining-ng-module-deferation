All six run for every decorated class — component, directive, pipe, service.

The backend produces two outputs from the same analysis: the type-check blocks, and the code that replaces the decorator.

Frontend — understands decorators and how they are interconnected. Global and slow.

Backend — transforms file by file. Local and fast.

Six phases, and every decorated class goes through all six. Every phase here exists to compile the decorator. That is the entire job. Your class body, your methods, your types — none of that enters this pipeline. It goes through TypeScript exactly as it always would. And it is every decorator, not only components. A pipe goes through these six. A service goes through these six. Only the template work is component-only. Detect finds the decorated classes. Analyze reads what is inside each decorator. Resolve is the one that needs the rest of your program. A template says cat-bean-grid, or uses the currency pipe, and the compiler has to find the class behind that name. The answer is not in the file. It is spread across your imports and your NgModules, so this phase cannot finish until it has seen everything. Those first three are the whole of the frontend. Nothing has been written anywhere yet — it is all metadata, held in memory. Everything after them is the backend, and the backend's job is to generate code. It does that twice, from the same analysis, and the two outputs do not depend on each other. The first is the one nobody guesses. TypeScript cannot read Angular templates. So Angular rewrites each template as TypeScript — a Type Check Block — lets TypeScript's own checker find the errors, maps them back onto your HTML, and drops the blocks. They never reach disk and they never ship. That is where the error comes from when you misspell a property inside double curly braces. The second output is the code that actually runs. Two phases build it, and they look like one. The difference is small but it is worth having. Compile builds the definition. For a component, defineComponent gets built, ready to be assigned to ɵcmp. But at the end of compile nothing has been written anywhere. It is an object in memory, in Angular's own format. Your class has not changed yet and your decorator is still on it. Emit is where it lands. Angular translates that object into TypeScript's own form, puts it on the class as a static property, deletes the decorator, and prints the file. So compile makes the content. Emit makes the file. And emit is the only one of the six that writes back into TypeScript. It runs as a TypeScript custom transformer — ts.Transformer. The first five read from TypeScript's compiler; this is the one that hands it something. Angular gives TypeScript a function, and TypeScript calls it during its own emit. One detail that surprises people: what gets printed is not always JavaScript. This repository sets isolatedModules, which tells Angular to apply only its own transformation and leave the rest of the TypeScript alone. So what the bundler receives here is TypeScript, and esbuild or Rspack does the rest. Now the two halves. The frontend understands the decorator: global, and slow, because it cannot finish until it has seen everything. The backend writes code — both kinds of it: file by file, and fast. Only one of those halves has been rewritten so far. [Say "every one of these exists to compile the decorator" before walking the table.
