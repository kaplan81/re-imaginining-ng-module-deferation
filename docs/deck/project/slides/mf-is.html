Every box publishes a remoteEntry. The addresses in them can change without rebuilding anything.

So that third moment — resolving a name while the application is already running — has a name of its own once somebody wraps a protocol around it. It is called Module Federation. And the first thing to say is the thing most people have backwards. It is not a library. It is a mental model: a few roles, and a contract between them. Implementations exist, several of them, and they are quite different pieces of software — but what they implement is this picture. Three applications. Look at them before anything else and notice that they are the same kind of thing. Not a framework and its plugins. Not a parent and its children. Three identical boxes. Only the labels differ. One is playing host — and an application in that role is usually called the shell. The other two are playing remote. What a remote offers, it offers by name. One of these exposes its routes, the other exposes widgets, and that is all either of them offers. Everything else inside stays private; the host has no way to reach it. Now the part worth pausing on. Every one of the three publishes a remoteEntry. Not just the remotes. The host does too, and in the application we will look at later the shell's remoteEntry lists no exposes at all — an empty array — while still carrying the full shared table. Which tells you that host and remote are not opposites, and not ranks. They are roles. The same application can be a remote to the thing above it and a host to something it loads itself, at the same time. And look at the arrows, because they run both ways on purpose. A remote is not only a thing that gets consumed. It can consume back — load something the host exposes, or something a sibling exposes. The relationship is allowed to be circular, and in real systems it often is. Nothing in the model says this has to be a tree. And because each one is served from its own URL, you can simply open a remote in a browser and use it on its own. It is a complete application. It does not need the shell to exist. Which is also what makes the addresses changeable. None of this was decided at build time, so a remote can move tomorrow, or a new one can appear, and nothing has to be rebuilt for that to work. Then the band along the bottom: shared. Without it, three applications each bring their own Angular, and the browser runs three copies of the framework with three injector trees. Shared is the agreement that stops that — and it is more than a list of names. Each entry carries the version range it needs, the version it was built against, and whether it must be a singleton. At load time those get negotiated, and one copy wins. [Walk the three boxes first and say "these are the same kind of thing". Then the remoteEntry on all three. Then the shared band.]
