3 - Bundlers

Rspack pipeline

Why it could be an option

Runtime plugins for extending federation behaviour.

Hooks around the federation lifecycle.

Chunk URL rewriting is possible, unlike in Native Federation.

The loader itself, remoteEntry.js, is replaceable.

Seamless integration with Zephyr Cloud.

Now the other one, and here there is a case. Runtime plugins, and hooks around the federation lifecycle. The federation runtime exposes a registration API for both, so you can extend what happens when a remote is resolved, loaded or shared. There is nothing equivalent on the other side. Chunk URL rewriting. Rspack works out every chunk address from a variable it keeps in the runtime it ships with your application, so those addresses can be moved while the application is live. Native Federation never writes them anywhere you can reach. The loader is replaceable. A remote entry here is executable JavaScript rather than a manifest of data, which means it can be swapped, wrapped or generated. A JSON file cannot. And Zephyr Cloud builds on exactly those last two. Deploy a remote, every host picks it up, with version history and rollback, and nobody rebuilds anything. One caution to keep in your pocket. Seven of this bundler's defaults turned out to be silently fatal once federation was in play, and three of them broke only the dev server while the production build stayed green. That is not on the slide, but it is the thing you will meet in week one. [Five lines. Chunk URLs and the replaceable loader are the two Native Federation cannot match.]
