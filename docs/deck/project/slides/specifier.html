1 - Modules

Let us start from the beginning

import { Component } from '@angular/core'

That quoted string is a specifier. It names a module — in practice, a file — but says nothing about where that file is.

Something has to turn it into a file a browser can fetch.

So: who turns that string into a file? Here is a line that has to appear in every component file ever written, because the decorator has to come from somewhere. Import Component, from at-angular-slash-core. Look at the part in quotes. That string has a name — it is called a specifier — and the thing worth noticing is what it is not. It is not a path. It is not a file name. It is not a URL. There is no folder called at-angular-slash-core sitting on a disk somewhere, and there is certainly no file by that name on a web server. It is a name. Somebody, at some point, has to look that name up and decide which actual file it means. A browser cannot do that on its own. Hand a browser that string inside an import and it will refuse it — failed to resolve module specifier — because as far as the web platform is concerned, that is not an address at all. So something has to resolve it. What that something is, and when it runs, is not the same in every Angular application. [One line on screen. Say it, then let the room look at it. The weight is on "a name, not a location".]
