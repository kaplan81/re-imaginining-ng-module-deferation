2 - Module Federation

Modules can be federated

Code splitting

Chunks from your own build.
Fetched when they are needed.

Federation

Chunks from a different build,
on a different server.

Code splitting: one build. Federation: several builds, interconnected.

Each federated module has its own build, its own deployment, its own URL.

The one that loads is the host. The one being loaded is the remote.

We have spent a while on modules, so let us put federation where it belongs. It is something that can happen to a module, and the closest thing to it is something everybody here already does. Code splitting. A dynamic import, a chunk that is not downloaded until somebody opens that route. Nothing about that is exotic any more. Federation is the same shape, with one thing changed. The chunk comes from a different build. A different compile, on a different schedule, deployed to a different server — and your bundler never saw it. So it is not bundled against not bundled. Both of these are bundles. Both arrive on demand. The only difference is which build produced the thing you are fetching, and that single difference is what forces the resolution into the third moment. Your build could not have resolved an address that did not exist yet. Worth comparing to how this is normally done, because the contrast is sharp. Today, if one team has a component another team wants, it goes to a registry: publish the package, the other team installs it, rebuilds their entire application, and deploys. Three steps and two builds, for a change of text. Federated, the first team deploys. That is the whole procedure. The second application points at a URL and picks up whatever is there the next time somebody loads the page. Three consequences, and they are the whole of what this buys. Independence. A federated module has its own build, its own deployment, its own URL. The dependency can point both ways. This is not a parent and a child. Two applications can each load from the other, and in real systems they often do. And the vocabulary, which everything after this uses. In any one exchange, the side doing the loading is the host. The side being loaded is the remote. Roles in a transaction, not ranks — which is why both ways round is possible at all. [Lead with code splitting — they already know it. The whole slide is one changed word: whose build.]
