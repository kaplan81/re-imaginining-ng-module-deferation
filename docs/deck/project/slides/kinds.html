1 - Modules

The four types of specifier

TypeExample
Relative URL path./util.js
Absolute URL path/lib/util.js
Full URLhttps://cdn.example/x.js
Bare specifier@angular/core

The first three tell a browser where the module’s file is. A bare specifier does not.

There are four types, and the difference between them is the whole of this section. A relative URL path. Dot-slash util-dot-js. Relative to the file doing the importing. An absolute URL path. Slash-lib-slash-util-dot-js. From the root of the site. A full URL. A complete address, pointing at any server you like. And a bare specifier. At-angular-slash-core — the one from the slide before. The first three are locations. A browser can take any of them and go and fetch the file, with no help from anybody. The third one could be pasted into an address bar. The fourth is not a location. There is no server anywhere with a folder called lodash. It is a name, and names have to be looked up by somebody. And this is the type that matters here, because it is the only one a browser cannot resolve by itself. At-angular-slash-core. Rxjs. Names, with no location attached. Which is why handing a browser a bare specifier gets it refused — failed to resolve module specifier. Not because the file is missing. Because nothing ever told it where to look. [Four rows. Read the types, do not read the examples — they are on screen. The time goes on the fourth.]
